# Zan 车搭：DIY 与 AI 车衣

## 使用

- `npm run dev`：本地开发，页面和 AI 接口共用 Vite 服务。
- `npm run build && npm start`：运行构建后的页面与 Node AI 服务，默认 `http://127.0.0.1:4173`。可用 `PORT` / `HOST` 更改监听地址。
- 需要 Node.js 24。服务端读取根目录 `.env.local` 的 `AI_GATEWAY_API_KEY` 和 `AI_GATEWAY_BASE_URL`；系统环境变量优先。密钥文件不进入前端构建，并已加入忽略规则。
- 模型固定为用户指定的 `gpt-image-2.5-flare`。

进入「车身外观 → DIY 车衣」，选择七个车身区域之一，上传 PNG/JPG/WebP，可拖动、缩放、旋转、调整透明度与底色；左右侧可以复制图案。配置保存在 localStorage，图片保存在同源 IndexedDB。保存的方案引用不可变图片，恢复时保留各面变换参数。自定义方案通过渲染 PNG 分享，不生成缺失本地图片的配置链接。

进入「AI 车衣」，需上传 1–6 张参考图，固定生成一张七面整车图集。生成后先显示结果，点击应用才替换车衣。整车应用会替换全部七面图案；历史单面结果仍可恢复应用。结果图及参考元素保存在当前浏览器，生成图可以继续在 DIY 中调整。取消操作停止等待并中断本地上游请求，不承诺撤销已经发生的供应商计费。

## 接口与文件

- 文档依据：https://qima.feishu.cn/wiki/L41twaq5Pi3FLukWmxFcvBwgnZ9
- 网关测试环境：`http://aigateway.prod.qima-inc.com/yz/v1`。每次生成均调用 `images/edits`，第一张为自动绘制的标注模板，后续为最多六张用户元素图，使用文档规定的 `images: [{image_url: dataURI}]` JSON 协议。
- `server/ai-wrap.mjs`：鉴权、请求验证、固定模型、提示词、超时、单并发限制、脱敏错误。密钥仅在服务端发往所配置网关。失败不会自动重试付费请求。
- `src/data/aiLayout.ts`：1024×1024 IP 风格七面布局（`ip-atlas-v2`）；旧 1536×1024 结果保留旧裁切规则，是服务端提示词与客户端裁切共同依据。
- `src/data/aiWrap.ts`：生成布局引导图、提交参考图、保存结果、按布局拆分并导入 DIY。
- `src/components/DIYEditor.tsx`：DIY 编辑器、AI 参考图/结果预览与应用。
- `src/viewer/livery.ts`、`diyAtlas.ts`：七面投影与 PBR 材质混合；不覆盖玻璃、轮胎和灯具。
- `server/start.mjs`：构建产物静态服务与同源 AI 接口。不能仅上传 dist 到纯静态托管后就期待 AI 可用。

## 2026-09-16 分区模板与上传区

- `public/templates/ip-wrap-template.svg`：依据用户 IP 参考图的矩形排布重建空白标注图，原参考图片未修改。上方为左右侧，中段为前后保险杠，下方为引擎盖、车顶、尾厢盖；右上两块是底色色块及保留区，不映射车身。旧 IP 预设只采样侧面、引擎盖与底色，因此其余面是新明确的映射约定，并非声称复原原图全部 UV。
- `aiLayout.ts` 同时定义模板 SVG、生成提示使用坐标和裁切坐标。所有区块在存储图里上方朝上，应用时按各面实际比例恢复。保留黑色间隔，生成提示要求移除文字、方向箭头；模型仍可能偏离要求，需验收生成结果。

- 此轮仅执行 npm test（28/28）及 npm run build，未做浏览器验收及付费模型调用。
- 颜色使用自有名称；基色与金属度参考官方展厅公开材质数据，记录在 `assets/materials/showroom-color-reference.json`。未找到可直接用于屏幕渲染的官方工厂补漆色号，不宣称实车色彩精确匹配。液态金属枪灰保持原值。

用户 prompt 输入已删除，旧本机草稿中的 prompt 不再读取；服务端拒绝带 prompt 字段的请求。固定设计要求见 `docs/ai-prompt-current.md`，修改前代码原文见 `docs/ai-prompt-before.md`。本次仅代码测试和构建，未验证新提示词的真实生图质量。

## 当前已接入：第九轮二次定位

用户已明确要求接入并自行重新生成验收。每次生成串行调用两次 `images/edits`：第一次设计，第二次以第一步返回的图片为唯一输入，沿用第九轮的 ONE FIFTH、三个中心坐标及定位边界。提示词从猫泛化为用户主题元素，保留底色，明确不生成透明背景。最终仅保存/预览/下载/应用第二步的图片。失败不自动重试，不把未经定位的初稿当成功结果返回；响应保留两次request ID。总服务超时10分钟，前端10.5分钟，取消共享同一个AbortController。

服务版本 `round-nine-two-stage-v1`，页面说明一次生成包含两次AI调用。34项代码测试与构建通过；本轮没有额外付费生成，复用第九轮实测依据，新的整条链路由用户生成验收。模型仍可能轻微偏离定位边界，不承诺硬约束。


## 当前清晰度修复（hires-two-stage-v2，覆盖上文固定缩小描述）

- 两次生图都请求2048×2048，提示词全部使用该画布的实际坐标。第二步追加布局模板，按目标安全矩形同比缩放，不再无条件缩为1/5。仍是两次付费请求，仍非透明图。
- storeImage的preserveResolution模式直接保存原始Blob，不经过Canvas重编码或1536边长压缩。生成结果、AI整车图导入和分面图使用该模式；普通参考元素仍采用原来的体积限制。生成文件上限32MiB、像素总量仍不超过32MP。
- applyAIResult根据源图实际像素和目标面比例确定裁切输出，输出宽高均不小于源区域像素，不再固定512高。
- DIY运行时图集每格最高2048×1024，4列2行，共8192×2048（RGBA约64MiB，不含Canvas副本）。根据GPU最大纹理尺寸回退，例如4096上限时每格1024×512。一次绘制入图集，移除中间画布的重复采样。UV分区、车身投影方向、现有预设保持不变，边缘半像素修正按实际格子尺寸计算。
- 实测完整两阶段各两轮（共4次上游调用）：11轮为坐标混用导致分区错误的失败样本；12轮改为2048坐标并在修图阶段带模板，返回实际2048×2048图，细节改善、七面排布恢复。原始结果、请求ID与耗时见 artifacts/ai-wrap-tests/11-* 和12-*。12轮耗时87秒；主体仍超出安全区，不宣称构图或边界已经稳定。
- 37项代码测试及构建通过，覆盖原始Blob保留、两次2048请求、裁切像素不降低、GPU尺寸上限。没有本轮浏览器3D或真机GPU验收。已保存的低清图无法找回丢失细节，需要重新生成或导入高清原图。
