# 开发规划与开工条件

2026-09-15。仅计划，不代表以下功能已经实现。

## 交付顺序

| 阶段 | 交付物 | 验收重点 | 预计工程量 |
| --- | --- | --- | --- |
| 1. 渲染基线 | 单页工程、一个样例车、环境与相机、触摸操作 | 模型可加载；真机初探能建立 WebGL 2；失败态可用 | 3–4 人日 |
| 2. 配置闭环 | 两车型切换、12 色、4 类膜面、车身绑定 | 玻璃/轮胎不被误染；车型切换保留膜色；快速切换无串车 | 5–7 人日 |
| 3. 完整 H5 | 移动布局、方案本机保存/恢复、重置、截图预览 | 关闭重进可恢复；配置版本变更可回退；异常操作可恢复 | 5–7 人日 |
| 4. 微信与性能 | 商家 web-view 接入、资源优化、真机调优 | 域名可打开；触摸正常；后台恢复；按实际机型记录性能 | 7–9 人日 |
| 5. 验收交付 | 回归修复、部署配置、接入说明、维护交接 | 商家车型和素材通过约定验收；配置可回滚 | 5–8 人日 |

合计约 25–35 人日，对应单人约 5–7 个工作周的排期预算。阶段之间可能重叠；这是工程估算，不是本轮研究耗时或确定交付日。等待商家素材、域名配置、设备或接口的时间另计。未将高级彩绘、自由贴纸、后台和订单纳入该范围。

## 第一阶段的最小开工包

技术路线及依赖版本有据可查；至少两个完整车辆样例及一个 HDR 环境已在本地；样例具有可明确映射的车身材质；模型与许可文件齐全；颜色/膜面参数样本齐全；模型结构和格式检查有记录；目标目录已建立。

满足上述条件即可开始网站研发。开工使用低面数样例并不验证最终写实画质、商家车型适配耗时或手机性能上限。第一阶段应尽早引入一台具有生产代表性的授权车辆做画质及预算复核。

## 后续必须由商家落实的内容

| 内容 | 何时需要 | 缺失时影响 |
| --- | --- | --- |
| 支持 web-view 的小程序及配置业务域名的权限 | 阶段 4 前 | 可开发普通 H5，不能完成正式容器验收 |
| HTTPS 域名、静态托管/CDN及发布方式 | 集成测试/上线前 | 本地可验证，正式入口无法交付 |
| 最终车型、可用于 Web 展示及客户交付的授权 | 最终车型接入前 | 只能用已收集样例验收软件流程 |
| 实际车膜名称、SKU、色卡/实物、质感参考 | 品牌内容及效果验收前 | 只能展示明确标识的示例颜色和近似质感 |
| 约定 iOS/Android 微信真机 | 性能验收前 | 无法证明微信兼容性与性能达标 |
| 原生分享/相册/云方案接口 | 仅新增这些需求时 | 首版仍为 H5 截图预览与本机存储 |

以上是后续联调/上线依赖，不把尚未拿到的账号或商业模型描述成已经完成，也不要求在开始基础研发前全部到齐。

## 验收用例

1. 默认车型正常加载；缺网、坏文件和未知配置显示明确错误，可重试。
2. 每台车型分别切换所有示例颜色与质感；只有声明的车身表面改变。
3. 快速连续切换车型、切后台后返回，最终车型始终对应最后一次选择。
4. 单指旋转、双指缩放、视角复位可用；操作下方色板不误触相机。
5. 保存后刷新恢复一致；损坏/旧版本配置能回退；存储被禁用时仍可操作。
6. 截图与当时车型、膜色、视角一致；微信和浏览器的可保存路径分别验证。
7. 无 WebGL 2 或上下文丢失时有降级/恢复行为，不持续白屏或循环重载。
8. 用正式代表车型检查首屏、持续旋转、切车循环和资源释放；预算见技术方案，记录未达标机型和降级结果。

## 当前阶段的停止点

整理方案、收集和校验素材、检查依赖，完成后报告开工状态。本轮不创建网站应用、不启动业务开发、不部署到公网。
