# 成品车衣构图规律与本站适配

依据用户本轮提供的七张图（第4、6张是同一款）。以下是可见构图的观察，不是对原图全部UV部位的复原，也不是实车施工标准。

| 参考款 | 可见规律 | 提炼成生成规则 |
| --- | --- | --- |
| Hello Kitty | 两条侧面图的主体集中中段偏下，顶部及两端大量底色，多个其它分区纯色 | 局部主题组团，留出干净背景，不将七面都画满 |
| 草莓熊 | 斜色带延伸很长，角色只占局部，其它分区几乎全纯色 | 背景可以满幅，主体不要随背景一起满幅放大 |
| 粉色卡比 | 主角色、标题及小元素聚成一组，周围大面积低信息背景 | 辅助元素围绕共同重心，不均匀撒满 |
| 动感卡比（重复两张） | 大幅流动图形承托局部角色，左右构图不同，其余多用条带或背景呼应 | 动感来自背景走势；左右可以变化，但属于同一套设计 |
| Labubu | 多角色有明显大小层次，主要角色靠近中段，小角色向两边延伸 | 不规定角色数量，保持主次和可读的核心组团 |
| 宝可梦 | 多角色沿侧面下部排列，光芒与渐变延伸至整个背景，其它区域简化 | 可以丰富，但重要面部需进入本站安全区，不能直接照搬满幅角色布局 |

参考中部分文字是镜像、部分图案沿边裁切或旋转存放；这些与原贴图的映射有关，不作为本站的通用设计规则照搬。

## 实际生成规则

`server/wrap-design-rules.mjs` 参与每次真实请求：侧面主视觉、背景与主体分层、可选极简/组团/动感构图、其它面有意减弱、左右呼应而非文字镜像、关键主体避开裁切区。只提取构图规律，不会自动把这些IP图片提交给模型，避免把示例角色混入用户的设计。

`src/data/wrapPlacement.ts` 定义内部模板安全区。按用户最终选择，只在空白模板上绘制醒目绿色虚线框及“主体完整放入绿框”说明；侧面框位于x=30%–70%、y=45%–77%，框外用于背景。各面均有定位框。这是针对本站原有投影的保守指导范围，并非实车精确UV。

渲染端恢复原始引擎盖和侧面采样，不缩放或重排生成结果。引擎盖模板标注“头朝下”，提示词要求上下翻转、左右不变，以适配原有渲染方向。静态模板与真实提交模板均来自同一templateSVG函数。安全区指导不能保证模型一定遵守，实际结果由用户验收。服务端status和生成返回携带safe-template-v2版本标记，用于识别旧服务。

32项代码测试及生产构建通过。未进行付费生图或浏览器验收。
